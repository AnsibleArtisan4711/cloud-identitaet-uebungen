## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Dynamische Gruppe | Mitgliedschaft ergibt sich aus einer Regel über Benutzerattribute |
| Zugewiesene Gruppe | Mitglieder werden von Hand eingetragen |
| Regel | Ausdruck wie `user.department -eq "Vertrieb"` |
| Verwaltungsrolle | Satz von Berechtigungen für Verwaltungsaufgaben |
| Kleinste Berechtigung | nur die Rechte, die für die Aufgabe nötig sind |

### Aufgabe 3 – Rollen (Einheit 2.3)

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

1. Siehe `beispiele/gruppen.ausgabe.txt`: Befehlsprüfung für `ad group create`, `ad group member add` und `role assignment create`: alle Parameter vorhanden.
2. Vier Benutzer: `ana` und `dora` (Vertrieb), `ben` und `cem` (Technik).
3. `technik-zugewiesen` mit `ben`; `vertrieb-dynamisch` hat 2 Mitglieder (`ana`, `dora`); das Hinzufügen von `cem` scheitert: „… ist dynamisch; die Mitglieder bestimmt die Regel, manuelles Hinzufügen ist nicht möglich“.
4. `nicht-vertrieb` (`-ne "Vertrieb"`): `ben`, `cem`; `ana-oder-technik` (`-startsWith "ana" -or … -eq "Technik"`): `ana`, `ben`, `cem`; die Regel `user.department = Vertrieb` scheitert mit „Regelfehler“.
5. Rollen (im Modell erfundene Zuordnung): `ben` darf `user.resetPassword` (JA), `user.create` (NEIN); `cem` darf `ca.manage` (JA, Conditional Access Administrator); `ana` darf `ca.manage` nicht.
**Lizenz:** Laut dem gelesenen Microsoft-Learn-Auszug (20.11.2026) gehören dynamische Gruppen zu den Funktionen von Entra ID P1 oder P2; das Modell prüft das nicht.

**Kontrollfragen (Antwortskizzen):**

1. `ana` und `dora` (Abteilung Vertrieb).
2. `ana`, `ben` und `cem`.
3. „Regelfehler“: Das Modell erwartet `-eq`, `-ne` oder `-startsWith` mit Wert in Anführungszeichen.
4. Kennwörter zurücksetzen (JA), Benutzer anlegen (NEIN); Zuordnung im Modell erfunden.
